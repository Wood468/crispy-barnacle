# Phases 3–6: forms, synced state, alerts, screenshot import

## What is where
| Phase | Files | Production effect |
|---|---|---|
| 3 Forms | `public/forms.json` (built by `tools/build_forms.py` from PokeAPI), `public/lib.js`, Collect → Forms | none until you mark something; marks are `form:<dex>:<key>` entries |
| 4 Synced state | `src/userstate.js`, `migrations/0002`, `/api/userstate` | table is created only by the PIN-protected init; until then everything stays on the device |
| 5 Alerts | `src/notify.js`, `migrations/0003`, `/api/notify/*`, `public/sw.js`, Saved → Alerts | sends nothing until `NOTIFY=1`, tables exist, you switch it on, and a channel is configured |
| 6 Import | `public/extra.js` (Collect → Import) | client-side only; adds **Have** only, with undo |

## One-time steps to turn it on (production)
1. Open the site, Collect → Dex, enter your sync PIN.
2. Saved → Alerts → **Create them now**. Runs the additive migrations (new tables only) and the first event check.
3. In Cloudflare → Workers → go-field-notes → Settings → Variables, add plain variables `PIPELINE` = `1` and `NOTIFY` = `1`.
4. Telegram: in Telegram talk to @BotFather → `/newbot` → copy the token. Send any message to your new bot. Open `https://api.telegram.org/bot<TOKEN>/getUpdates` in a browser and copy `chat.id`. Add **secrets** `TELEGRAM_BOT_TOKEN` and `TELEGRAM_CHAT_ID`. Then Saved → Alerts → Send a test message.
5. Browser push (optional): on iPhone add the site to the Home Screen and open it from there, Saved → Alerts → Turn on for this device. Keys are generated by the server on first use (or set `VAPID_PUBLIC` / `VAPID_PRIVATE` secrets to supply your own).
6. Switch **Send me alerts** on. Off by default.

## Rules the code enforces (tests in `test/phases.test.mjs`)
* Only announced events (official or community reported, not conflicting, known start time) can alert.
* Datamined or conflicting information never produces an alert; datamine finds are an opt-in, labelled "NOT ANNOUNCED" digest.
* First run records a baseline and sends nothing for what already exists.
* Every alert has a dedupe key; failed sends are retried, successful ones never repeat.
* Missing/needed alerts use only marks you made (no marks → no alert); followed Pokémon always count.
* Web push is payload-less: the push wakes the service worker, which reads the message back using a hash of its own push address. Keys never leave the server.

## Schedule
`wrangler.toml` declares one cron, `30 20 * * *` (20:30 UTC): **7:30 am Melbourne during AEDT and 6:30 am during AEST**. It runs the datamine watch and, when `PIPELINE`/`NOTIFY` are `1`, discovery and alerts. A second `0 */6 * * *` cron (discovery + alerts only) was removed because the free Workers plan allows 5 cron triggers per account and the extra one made deploys fail (error 10072). The worker still supports it: add it back to `wrangler.toml` when a slot is free or the account is on Workers Paid. With daily checks, "starting soon" alerts are coarse; the window (default 12 h) is not an exact lead time.

## Known limits
* Screenshot reading uses Tesseract.js loaded from jsDelivr on first use (not testable from the build sandbox, so unverified on real GO screenshots). Pasting names works without it.
* The catalogue lists forms the series has; not all are in GO. Paldean Tauros breeds are separate catalogue entries, while events say "Paldean Tauros".
* iOS web push needs the site on the Home Screen (iOS 16.4+). Payload-less push on Apple's service is unverified.
